# Phase 6 — Activity Center

## Scope

Phase 6 adds an in-app activity inbox without introducing push delivery yet. The feature is intentionally built on top of the social actions already present in SnapGym so notification state remains server-authoritative.

### Events

- new follower;
- like on one of the user's check-ins;
- comment on one of the user's check-ins;
- participant joining a challenge created by the user.

### Client experience

- bell entry point on the Feed with unread badge;
- dedicated Activity screen;
- unread/read visual states;
- mark one notification as read when opened;
- mark all notifications as read;
- contextual navigation to profile, Feed or Ranking;
- pull-to-refresh.

### Backend rules

- clients cannot insert or delete notification rows;
- notification rows are generated by private trigger functions;
- authenticated users can only select/update their own notification rows;
- client-facing RPCs are `SECURITY INVOKER`;
- private trigger helpers are `SECURITY DEFINER`, have an empty `search_path`, and are not executable by public/anon/authenticated roles;
- likes use a deterministic dedupe key and removing a like removes its corresponding activity notification;
- covering indexes exist for notification foreign keys and inbox/unread lookups.

## QA

The hosted development project includes six synthetic QA actors and representative social interactions, providing all four activity event types without using real personal data. Three synthetic active challenges are also available for discovery, join and participant-count testing.

Automated coverage includes Flutter model/widget tests plus a transactional pgTAP suite that validates trigger generation, unread state transitions, RLS recipient isolation and like-notification removal. Database tests run in CI against a clean local Supabase stack.

Push notifications remain out of scope for this phase. FCM/APNs can consume the same event model later without making the mobile client authoritative for notification creation.
